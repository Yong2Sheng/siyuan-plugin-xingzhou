# 行舟 · 个人项目与事务中心

行舟是一个面向个人时间的思源笔记插件。它把原生属性视图保留为唯一数据源，在其上提供更适合浏览、选择和逐步展开项目的界面。

> 当前版本：`0.1.0`（首个只读测试版）

[English README](README.en.md) · [中文更新日志](CHANGELOG.md) · [English Changelog](CHANGELOG.en.md)

## 设计目标

- 降低“有私人时间时，我该做什么”的决策成本；
- 用同一个数据库捕获长期领域、项目、任务、事务和想法；
- 项目主页保存完整地图，数据库只管理当前需要被看见的工作项；
- 只记录直接上层关系，并据此恢复完整层级；
- 简单的一次性事务留在数据库，不强迫建立文档；
- 让界面跟随思源主题与深色模式；
- 不把个人项目管理变成新的绩效压力。

## v0.1 已实现

- 从指定的思源属性视图读取“全部工作项”；
- “长期领域”和“独立工作项”入口；
- 默认仅展开活跃路径，也可以全部收起；
- “全部 / 活跃项目 / 将来／也许 / 已结束”筛选；
- 详情页展示层级、状态、计划日期、截止日期、预计时长与所需精力；
- 以“本次行动细则”为主要内容，以“下一步行动”为辅助内容；
- 打开已关联的思源文档，或跳回原生数据库；
- 检查自指、多个直接上层、缺失父项、循环和顶层项目不一致；
- 加载、空数据、接口错误和缺失可选字段的状态提示；
- 适配思源主题变量和深色模式；
- 设置属性视图 ID 与数据库块 ID。

当前版本刻意保持只读：不会新增字段，不会改写工作项，也不会自动修复关系。`本周`、`收件箱`和`整理`页面仅保留入口，待“全部工作项”的模型稳定后继续实现。

## 数据库约定

行舟会按字段名称识别数据，当前约定如下：

| 字段 | 用途 | v0.1 |
| --- | --- | --- |
| 工作项 | 名称和关联块 | 必需 |
| 工作项类型 | 长期领域、项目、任务、事务、想法 | 建议 |
| 状态 | 收件箱、规划中、活跃、待开始、进行中、等待、阻塞、暂停、将来／也许、已完成、已失败、已取消、已放弃 | 建议 |
| 上层工作项 | 只指向直接上一级 | 建议 |
| 所属顶层项目 | 快速定位顶层项目 | 可选 |
| 本次行动细则 | 当前工作项要做的内容，详情页视觉主位 | 可选；缺失时兼容 |
| 下一步行动 | 明确存在前后关系时，记录随后要做的动作 | 可选 |
| 计划日期 | 安排到实际日期 | 可选 |
| 截止日期 | 只在存在真实期限时填写 | 可选 |
| 预计时长（分钟） | 当前可执行工作所需时间 | 可选 |
| 所需精力 | 低、中、高 | 可选 |

数据库应保存顶层项目、当前子项目和当前需要管理的可执行任务，不必复制项目主页里的全部拆分结果。

## 安装测试包

1. 下载发布附件中的 `package.zip`。
2. 在思源工作空间的 `data/plugins/` 下创建 `siyuan-plugin-xingzhou` 文件夹。
3. 将压缩包内容解压到该文件夹，确保 `plugin.json` 位于文件夹根部。
4. 重启思源或重新加载插件，然后在集市已下载插件中启用“行舟”。
5. 打开插件设置，确认属性视图 ID 和数据库块 ID。

## 本地开发

```bash
pnpm install
pnpm test
pnpm check
pnpm build
```

`pnpm build` 会生成 `dist/` 和可安装的 `package.zip`。

## 数据与隐私

- 行舟不包含远程服务；
- v0.1 只通过思源本地 API 读取配置的属性视图；
- 插件私有数据只保存两个绑定 ID；
- 插件不会访问其他工作空间，也不会扫描未配置的笔记本；
- `disabledInPublish` 已启用，避免在发布服务中加载个人管理界面。
