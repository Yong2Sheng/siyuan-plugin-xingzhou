# 行舟 · 个人行动与生活系统

行舟是一个由插件独立维护数据的思源个人行动与生活系统。“项目与事务”管理长期领域、项目、任务和想法；“生活节律”记录科研工作、身体状态、个人生活、恢复与营养摄入。所有数据都保存在插件内部，不要求用户另建数据库或文档来承载。

> 当前版本：`2.1.0`（目标切片做满即完成事务、今日个人安排可取消当天安排并显示事务结束状态、就寝时段与表单边界修复）

## 核心能力

- 一级模块分为“项目与事务”和“生活节律”；“全部／本周／整理／关系图”只属于项目与事务，“每日 Checklist／今日记录／营养摄入／历史数据／评分标准／时间线”只属于生活节律；
- 每日 Checklist 复用纸质版的工作日、周六和周日提醒内容，但不包含需要填写的字段；可在适合屏幕逐项查看的“行舟视图”和保留纸面观感的“纸质视图”之间切换，两种视图共享当日勾选状态；
- Checklist 的时间节点、标题和提醒内容均可编辑；每条提醒支持待处理、已完成、部分完成和未完成四种结果，部分完成按半项折算；显示偏好、模板、每日结果及周末训练安排按日期保存在独立的 `checklist.json` 中，重启插件或更换同步设备后仍可恢复；
- 营养摄入按日汇总热量、蛋白质、碳水和脂肪，不区分餐次；支持常用食物模板一键记录或按实际重量／容量比例换算，以及可选的每日热量和蛋白质目标；目标设置与模板编辑使用独立卡片，宽屏并列、平板与窄屏上下排列；
- 营养记录保存录入当时的模板快照；以后编辑或删除常用模板只影响后续录入，不会改写历史摄入数据；
- 生活节律支持科研工作日、开会日、周六轻量复盘、周日半日科研和休假／节假日五种日期类型；开会日适用于 conference、talk 和合作会议，会议结束后再选择是否安排个人事务，并跳过当日营养摄入记录；其他日期按星期给出默认值，也允许逐日覆盖；
- 每日表单按“早晨／午饭后／下班／下班后／21:00”时间动线分阶段填写，并支持自动保存；阶段按钮显示未开始、待补、完成或无需检查，顶部待补清单可直接跳转并聚焦遗漏的关键字段，同时保留自由跳跃填写，普通备注仍为可选；
- 午饭后专业学习先确认“没有／有”，只有确有安排时才显示书目、主题、计划和完成记录；手表睡眠评分和晨起体重先确认当天是否具备记录条件，选择“是”才显示输入框；睡眠时长使用小时＋分钟输入，体重支持 kg/lb，昨晚熄灯与今日起床保存为明确的跨日日期时间；昨晚熄灯可就寝时段选“12 点前／12 点后（熬夜）”，选 12 点后即可只留熬夜标记、不记具体分钟，填了时间则由时间自动判定时段、冲突项置灰，想清掉时间需自己点“清空”，历史列表会显示“熬夜”标记；睡前计划可选择当晚或次日熄灯，也可选择“自由安排”而不记录计划；
- 训练先确认完成状态，仅在“已完成”时展开训练内容；下班后的工作闭环明确区分“尚未确认／不需要／需要”，并进一步先判断是否有下一步，只有选择“有”才展开下一步内容；“不需要”的闭环时长按不适用保存而不是记为 0；
- 21:00 复盘先判断下班后是否处理工作、是否有异常或观察，只有选择“是”才展开对应说明，选择“否”无需再手写“没有”或“无”；
- 个人事务补充说明同样先确认“是／否”，只有选择“是”才展开输入框，选择“否”立即收起并保留已写内容，改回“是”即可恢复；旧记录中已有的补充说明会自动识别为“是”，不会因为新增判断而隐藏；
- “明天开始工作时的第一个动作”在 21:00 复盘填写后，会自动作为只读提示出现在次日早晨的“今日安排”中：仅供早上参考、不可编辑，前一天未填写时不显示；
- 休假日不显示科研字段，工作指标按“不适用”处理，不会作为未完成或零分进入后续分析；
- 事务可设置目标切片数和每片预计时长，并在日历中自由安排不构成上下层工作项的执行切片；完成进度以百分比显示，未完成或放弃会保留历史并释放新的待安排名额；日历右键可提前完成未来切片、完成今日切片或补记过期切片，且始终保留原计划日期；目标切片数最多 366 片，已标注在字段后，切片卡片采用一行式紧凑头部（说明收进 ⓘ 提示）；完成最后一片时事务自动同步为“已完成”，撤销完成后目标不再做满则退回“进行中”，已结束的事务不会被切片动作改写状态；
- 执行切片日历与“本周”同时提示当天“待做”时长（仍未完成的切片时长合计）：当天承诺的事全部做完或提前做完时，显示绿色“待做 0 分”并把整格标绿，便于把这天再安排给其他事务；旁边保留“共 X 分 · N 片”（已安排＋已完成）作为对照，日历头部还有一行汇总与口径说明；格子按宽度自动收敛写法，窄屏也不会只剩一个裸数字；
- 截止日期只限制切片最晚可安排日期；没有截止日期的事务仍可从今天起安排和移动切片；
- 已有执行切片不会阻止清除截止日期或改回“待确认”；重新设置具体日期时，仍会阻止日期早于已有切片；
- “本周”按切片显示每日执行安排；提前完成的切片保留在原计划日期，并在实际完成日显示一条不计入当日工作量的成就记录；“生活节律”的下班后个人安排会自动读取当天切片，也可从进行中的事务补充当天切片并立即同步回项目视图；每行可直接完成、放弃或取消当天安排（取消只撤切片、不动事务），事务已结束时该行仍保留并标出“事务已完成／事务已取消”，三个操作一并停用；
- “全部”页浏览长期领域、顶层项目、子项目、任务、事务和想法的完整层级；只有当天仍有未完成切片的事务显示蓝色“今日”，事务旁还会提示切片尚未设置、待安排、已全部安排或已完成；同级工作项可通过每行的上移、下移按钮或拖动手柄手动排序；
- “本周”继续兼容旧的计划日期与逐日完成记录；配置执行切片的事务改由切片决定每日安排，不再把开始日至截止日机械铺满；
- 从“项目与事务”切换到其他模块再返回，或者重新打开行舟时，都会恢复离开前的页面、筛选、层级展开、选中工作项和滚动位置；上次的事务已完成或不可见时，按“今日未完成切片最多（并列取树序第一）→ 树序第一个可见事务”的确定性顺序回落到可见事务；
- 新增工作项统一从“全部”页左侧的分类加号、详情中的添加下级按钮或层级右键菜单进入，创建时直接明确领域、项目、事务、想法及其层级；
- “整理”页分别列出“重点投入”的长期领域与“进行中”的顶层项目，用来区分近期重视什么和正在做什么，并继续检查遗留日期、行动细则与本周结果；旧“收件箱”状态条目仍可在“全部”中读取和调整，但界面不再创建新的收件箱条目；
- 直接编辑名称、类型、状态、上层工作项、计划开始日、截止日期、时长、精力与行动内容；“本次行动细则”和“下一步行动”在阅读态支持基础思源 Markdown 渲染，编辑框会按完整内容自动展开、自动续写列表，并在输入、删除、剪切或粘贴后立即校正同级编号；
- “本次行动细则”支持图片：直接粘贴截图或把图片文件拖到卡片上即可插入；图片按原分辨率存入思源资源库，细则里只保留 `assets/…` 路径引用，图片字节不进入插件数据；同名同内容只存一份，编辑态在输入框下方显示缩略图（上传中／失败／体积／可单张移除），阅读态按容器宽度限高显示，点击可看原图；
- 条目结束（已完成／已失败／已取消／已放弃）后，其自身与全部下级引用的图片进入 7 天待清理宽限期：宽限期内细则与图片原样保留，条目显示“图片待清理 · 还剩 N 天”角标；工具栏“清理图片”入口（带待清理条数角标）进入独立页面，列出待清理条目与缩略图，点“现在清理”在页内逐条逐张勾选范围后才执行；清理只删除思源确认“没有任何引用”的文件，仍被文档、数据库或其它未结束条目引用的图片会标明引用方并保留，删除的文件会先进思源历史目录，可找回；同页的“图库体检”给出图片数量、未结束占用、待清理占用、资源库总量与按条目占用排行；
- “完成后开始”和“需先行”可连接任意领域或项目中的工作项，并阻止自依赖和循环依赖；新增依赖时只列出“进行中”和“待开始”的候选事务；
- “关系图”自动显示全部未完成项目与事务直到长期领域的完整上下文，并用带方向说明的连线呈现上下层、“完成后开始”和“需先行”；支持搜索、筛选、缩放、拖动画布、关联高亮和从右侧栏打开详情；
- 可选关联思源文档，但独立工作项不需要建立文档；
- 删除工作项时保留下级工作项，并自动清除其他工作项对它的层级及依赖引用。

## 数据保存与迁移

完整工作项、同级顺序、旧版逐日完成日期和执行切片由插件私有的 `work-items.json` 保存。每次新增、编辑、排序、排期、切片处理、整体完成或删除时，行舟都会：

1. 在写入前把上一版轮换保存到三个内部备份文件之一；
2. 写入新的完整数据；
3. 重新读取并逐项比对，确认保存结果一致后才向界面返回成功；
4. 如果主数据无法识别，优先从最新的有效内部备份恢复；如果主数据和备份都损坏，则停止写入，避免静默覆盖。

从 `0.4.x` 升级且尚未存在内部数据时，插件会读取设置中指定的旧属性视图一次，连同旧版插件私有的跨项目依赖一起迁移，并保存迁移快照。迁移完成后，日常运行不再读取或修改旧属性视图。

因此，确认升级后能正常看到所有工作项以后，删除旧数据库或承载数据库的文档不会删除行舟内部的工作项。需要注意：如果某个工作项只保存了一个指向思源文档的关联，而该文档本身被删除，那么工作项仍在，但对应文档自然无法再打开。

本次架构改造前另有一份通过思源本地属性视图接口创建的人工快照，仅保留在开发者本机，不进入源码仓库或安装包，也不参与插件运行。

生活节律使用独立的 `daily-records.json`，首次打开时建立空仓库，不读取也不迁移“改变2026·每日数据”或其他思源文档。Checklist 模板、显示偏好和按日期保存的完成状态位于 `checklist.json`；营养目标、食物模板和每日摄入记录保存在 `nutrition.json`。工作项、生活节律记录、Checklist 配置与进度和营养记录分别维护修订号、三份轮换备份和写后复核。

## 生活节律读取接口

插件实例为后续统计或 AI 分析保留两个只读入口：

- `getDailyRecordsSnapshot({ from?, to? })`：读取完整记录或指定日期范围的不可变快照；
- `getDailyRubrics()`：读取当前版本的五套评分规则。

记录会保留日期类型和评分规则版本，因此休假日可从工作指标统计中排除，历史数据也不会被未来规则调整误读。

## 安装测试包

1. 下载构建产生的 `package.zip`。
2. 在思源工作空间的 `data/plugins/` 下创建 `siyuan-plugin-xingzhou` 文件夹。
3. 将压缩包内容解压到该文件夹，确保 `plugin.json` 位于根目录。
4. 重启思源或重新加载插件，在集市已下载插件中启用“行舟”。
5. 从旧版升级时，第一次打开后核对工作项数量、层级和依赖；设置中的两个旧数据库 ID 仅用于这一次导入。

## 本地开发

```bash
pnpm install
pnpm test
pnpm check
pnpm build
```

`pnpm build` 会生成 `dist/` 和可安装的 `package.zip`。

## 数据与隐私

- 行舟不包含远程服务；
- 完整工作项、每日记录、营养记录、迁移快照和轮换备份均由思源的插件私有数据机制保存；
- “本次行动细则”里的图片保存在思源资源库（`data/assets/`），插件数据只记录引用路径；图片会随思源云同步计入你的云端配额，清理功能与“图库体检”都只针对行舟引用的图片，不会删除笔记中的其它资源；
- 只有打开已关联文档以及首次旧版迁移需要访问思源本地内容；
- 插件不会自动创建或删除思源文档；
- `disabledInPublish` 已启用，避免在发布服务中加载个人管理界面。
