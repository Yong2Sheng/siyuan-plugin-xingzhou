# 架构与数据安全参考

仅在任务涉及持久化、迁移、恢复、工作项数据或思源 API 时读取。

## 主要职责

- `src/index.ts`：插件生命周期、页签和对话框入口、设置加载、变更串行队列、四类内部数据的加载/保存/恢复，以及一次性旧属性视图迁移。
- `src/internal-store.ts`：`work-items.json` 的解析、规范化、版本迁移、工作项增删改排序和轮换备份名称。
- `src/daily-records.ts`：`daily-records.json` 的记录规范化、更新、评分相关数据和备份名称。
- `src/checklist.ts`：`checklist.json` 的模板、显示偏好、每日进度、规范化和备份名称。
- `src/nutrition.ts`：`nutrition.json` 的目标、食物模板、摄入快照、规范化和备份名称。
- `src/work-items.ts`：旧属性视图读取与一次性迁移所需的数据解释，以及仍需使用的属性视图 API 操作。
- `src/siyuan-api.ts`：思源 API 响应码检查和统一错误类型。

## 必须保持的数据不变量

每个主仓库都以显式版本和单调递增的 `revision` 表示当前状态。修改保存路径时必须保持：

1. 在写主文件前，将当前有效状态写入由当前修订号选择的三槽轮换备份。
2. 主文件和备份写入后都重新加载，经过对应解析器规范化，再与预期对象完整比较。
3. 主文件不可识别时读取全部轮换备份，选择修订号最高的有效状态，并通过同一验证路径恢复主文件。
4. 主文件存在但不可识别、且备份均不可用时抛错并停止写入；只有确认为空或缺失时才能创建初始仓库。
5. 写操作经过 `mutationQueue` 串行化；快照读取等待已排队变更完成，并返回与内部状态分离的副本。
6. 解析器承担旧版本兼容和默认值补齐。新增字段不能只更新新建对象，还要更新旧数据解析、克隆、比较与相关测试。

## 迁移边界

- `work-items.json` 仅在内部主仓库尚不存在时尝试从旧属性视图导入，并保留迁移来源快照。
- 日常工作项读写以插件内部仓库为准，不应重新引入对旧属性视图的持续依赖。
- `daily-records.json`、`checklist.json` 和 `nutrition.json` 是独立仓库，不应从无关思源文档推断或导入数据。
- 任何可能改变存量数据含义的迁移都必须覆盖：当前版本、至少一个已发布旧版本、缺失字段、非法值、重复标识和恢复路径。

## 思源 API 操作

- 读取和修改文档结构时使用块级、属性视图、数据库或 SQL 接口定位明确对象。
- 禁止将 `/api/export/exportMdContent` 或任何导出内容作为可回写源，禁止导出后整体覆盖根块。
- 属性视图写入后重新渲染或读取对应数据并核对目标字段；删除后确认目标确实消失。
- 批量写入前确认 ID、父级、视图及目标集合，失败时保留足以定位问题的错误，不静默回退为空数据。
