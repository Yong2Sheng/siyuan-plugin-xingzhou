# 测试与界面参考

仅在任务涉及 Svelte 交互、布局、日期、排期或跨模块状态时读取。

## 测试选择

- 纯函数和领域规则：在对应 `tests/<module>.test.ts` 中覆盖输入、输出和边界，不依赖渲染组件才能证明规则正确。
- Svelte 组件：覆盖用户事件、条件显示、回调参数、异步完成后的界面状态，以及组件销毁后的清理。
- 跨模块壳层：使用 `AppShell.test.ts` 验证一级模块切换和共享回调；使用 `XingzhouApp.test.ts` 验证项目事务主界面的集成行为。
- 工作项与执行切片：同时检查层级、状态、排序、计划日期、截止日期、完成/放弃历史以及不同模块中的同步呈现。
- 日期规则：不要依赖测试运行机器的隐含 UTC 假设；覆盖本地日界线、周起点、跨月/跨年和时间字符串转换。
- 持久化字段：覆盖首次创建、从旧对象解析、保存后重载，以及将控制选项从“是”改为“否/不适用”时清除已隐藏内容。

## UI 判断

修改界面前先确定状态所有者，避免组件之间通过重复状态产生不同步。重点检查：

- 一级模块来回切换后，页面、筛选、选中项、展开状态和滚动位置是否符合既有约定。
- 自动保存期间连续输入时，旧的异步响应是否可能覆盖新状态。
- 条件区域隐藏后，数据是否应清除、保留或标记为不适用；用领域规则明确决定，不按视觉效果猜测。
- 宽屏与窄屏下是否出现嵌套滚动、内容截断、固定区域挤压或弹窗超出视口。
- 键盘输入、焦点跳转、Escape/关闭按钮、文本区自动高度和 Markdown 列表续写是否仍然可用。

## 验证顺序

先运行直接相关测试，再根据影响面运行 `pnpm run check`、完整测试和生产构建。组件测试通过不代表真实思源容器中的尺寸、滚动和页签生命周期一定正确；最终汇报应列出需要用户在思源中手动验证的具体操作路径。
